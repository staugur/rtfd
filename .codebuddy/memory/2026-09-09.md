## Dockerfile 中安装多版本 Python（回答用户追问，已落地）

- 方案选型：源码编译（慢、镜像大）／Ubuntu+deadsnakes PPA（仅 Ubuntu）／pyenv（默认源码编译）／**uv 预编译 CPython（推荐，快、任意版本）**。
- 实现：`COPY --from=ghcr.io/astral-sh/uv:0.4.20 /uv /usr/local/bin/uv`，`ENV UV_PYTHON_INSTALL_DIR=/opt/python`、`XDG_BIN_HOME=/usr/local/bin`；`uv python install $python_versions`，再 `ln -sf "$(uv python find $v)" /usr/local/bin/python$v` 并对每个版本 `python$v -m pip install virtualenv`（rtfd 用 `-m virtualenv` 建 venv）。
- 关键：光装解释器不够，必须用 sed 把 `版本号 = /usr/local/bin/pythonX.Y` 写进 `/rtfd.cfg` 的 `[py]` 分区（GNU sed `a` 语法），并固定 `default = 3`（否则默认版本取文件顺序第一个）。
- 构建参数：`--build-arg python_versions="3.9 3.12"`，置空则只用系统 python3；验证 `rtfd cfg py` / `rtfd cfg py 3.12`。
- 本机无 docker，未做真实构建验证；仅用 python3 等价模拟了配置写入并用 rtfd 二进制验证解析。

## TODO「优化nginx性能并增加缓存」分析与实现（配置层面）

- 分析结论：瓶颈在①主配置缺 gzip_types/min_length、tcp_nopush、open_file_cache、日志缓冲、多域名哈希表；②项目模板完全无缓存头；③生成的项目 conf 未被主配置 include（Docker 场景）。
- 实现：
  - `scripts/nginx.conf` 重写：sendfile+tcp_nopush/nodelay、keepalive_requests 1000、gzip(含 gzip_types/gzip_min_length/gzip_static)、open_file_cache(max=10000 inactive/valid 30s)、etag+if_modified_since before、access_log buffer=64k flush=5s、server_names_hash_*、include /rtfd/nginx/*.conf 与 ext。
  - `pkg/lib/nginx.go` 模板分级缓存：静态资源 location（`^/(_static|_images|_downloads)/|\.(css|js|png|jpe?g|gif|ico|svg|woff2?|ttf|eot)$`）→ `expires Ns` + `Cache-Control: public` + access_log off；HTML → `no-cache`（多版本放在 `location /` 内，避免新增 location 抢走 302 逻辑；单版本用 `~* \.html$`）；可选 open_file_cache。新增 nginxOptions 字段 StaticExpires/HTMLNoCache/OpenFileCache。
  - `[nginx]` 新增键：static_expires(默认3600)、html_nocache(默认on)、open_file_cache(默认on)；renderNginx 用 MustKey+gtc.IsTrue 读取，非正整数归一为空。
- 顺带修复既有 bug：未配置 conf_ext_dir 时 cstNgxFile==dftNgxFile，清理自定义域名配置的分支会把刚生成的默认配置删除（现加 `cstNgxFile != dftNgxFile` 守卫）。
- 测试：新增 TestRenderNginxCache；更新 TestRenderNginx 的 location 数量断言（多版本2、单版本1）。gofmt/vet/test/staticcheck 全绿；用本地 redis 端到端验证了多版本/单版本/关闭缓存三种渲染结果。
